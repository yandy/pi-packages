# pi-context-insight 报告 UI 重排设计

日期：2026-11-23
状态：设计已定，待实现
参考：`~/workspace/refs/vibecoding/dsh-context`（DeepSeek Harness 的 context 插件，卡片栅格 + 主从布局的实物参考）

## 意图与理由

`/insight` 生成的单文件 HTML 数据是全的，但页面是 10 张卡竖着堆到 6000px：Token / 耗时两张卡左边只放一个 96px 环，右边表格撑满 1400px 宽，左半页空白；「上下文浏览器」把 10 个分类 × 最多 200 条平铺成一条连续列表，单步就能刷出 800px 以上折叠行；时间线 SVG 最小宽 720px 却放在 1400px 的卡里，右半边空着。另外报告里有"看得见但不工作"的东西：8 个工具栏按钮中「轮次 / 自适应 / 耗时」无任何效果，`browser.system` 这个 i18n 键根本不存在导致分类标题直接渲染成 `browser.system`，JS 重绘后条目 chip 退回内部 id（`systemBase`、`toolDefinitions`、`toolCalls`）。读起来不像一份成品报告，像调试页面。

要的是：一眼能看出结构和比例，能按分类下钻，所有按钮按下去都有反馈，中文报告里不出现内部键。

## 目标

- 首屏（1440×900）能看到 KPI 条 + 主干导航，不用滚就知道这份 session 的形状。
- 卡片按内容分栏，不留结构性空白；整页纵向长度相比现状至少缩短 40%。
- 每个交互按钮都有可观察的效果，或者不存在。
- 中文报告里所有可见文本都来自词典（含 JS 重绘出来的部分）。
- 单文件、离线、严格 CSP 的约束不变。

## 非目标

- 不做浅色主题（暗色令牌预留结构，另开）。
- 不引入图表库、图标字体、外部资源（CSP 与离线约束）。
- 不改数据口径：用量聚合范围、估算规则、裁剪与降级链、`--short` 的正文剥离规则全部不动。
- 不做 dsh 那种跨 session 的 Insights 页与会话卡片（本包只有一个 session 的报告）。
- 不重写 payload schema；允许在 `schema: 2` 上**追加**客户端重绘所需的字段（见 §5），不删不改既有字段语义。

## 反目标

- 为了好看把数字改小、加省略号导致比例失真。
- 引入"看起来像交互"的装饰（hover 有反应、点击无逻辑）。
- 用 CSS 缩放把现有 720px SVG 硬拉到整宽（横向变形）。

## 约束

- 单 HTML + 内联 CSS/JS/JSON；CSP `default-src 'none'`，无 `eval`，无外部请求。
- HTML 预算 16 MB，超出按 `bodyScale` → `detailSteps` 顺序降级；本次改动只增加 CSS/JS 各几 KB。
- 报告必须容忍 JS 不执行：静态部分（含默认视图的时间线）要自己站得住。
- i18n 必须 en/zh 键集完全相同（现有测试强制）。
- 浏览器目标：Chromium 与 Firefox 近两年版本；无 polyfill。

## 方案与取舍

**A 只换皮**（只重写 `REPORT_CSS`）— 风险最低、测试几乎不动，但 6000px 长页、卡内空白、平铺列表这三件事只解决一小半，因为它们是 DOM 结构问题。

**B 换皮 + 布局重建** — 贴参考：左侧固定段导航、顶部 KPI 条、12 列卡片栅格、浏览器主从布局。解决布局，但裸 id 与死按钮仍在，新皮盖不住"按了没反应"。

**C = B + 修掉假交互与裸 id**（选定）— 在 B 的基础上把 i18n 缺口、内部 id 泄漏、无响应开关一并处理。改动面最大（贯穿全部 render 模块、runtime、i18n 与测试），但它是唯一能让报告"经得起看"的选项。用户已确认选 C。

## 设计

### 1. 页面壳体

```
+---------------------------------------------------------------+
| rail 220px (sticky)      | main  max-width 1180px              |
|  会话标题                |  <section> 卡片栅格                 |
|  模式徽章 · 生成时间      |                                     |
|  session meta 两行       |                                     |
|  nav 10 项（当前段高亮）  |                                     |
|  EN / 中文               |                                     |
+---------------------------------------------------------------+
```

- rail 用 `position:sticky`，`IntersectionObserver` 高亮当前段；点击锚点平滑滚动（`scroll-behavior:smooth`，`prefers-reduced-motion` 下关闭）。
- 窄屏 ≤ 900px：rail 折成顶部横条（当前 nav 的样子），栅格全部单列。
- 打印：`@media print` 隐藏 rail 与面包屑，main 全宽，卡片 `break-inside:avoid`，折叠内容不展开。

### 4. 各卡布局

**KPI**：label 11 大写、值 22/600、sub 11 dim。成本卡右上角 chip 显示口径（`provider 上报` / `目录估算` / `混合口径`）。

**Token 构成**：132px donut（中心合计 14px + 副标 9px）+ 右侧两列图例。每条图例是一行：`● 类别 ……… ≈值 · 占比 · 40px 微条`。不再用表头表格；成本移入 `title` 属性，卡片 meta 写"成本按占比分摊"。

**耗时**：同构——132px donut + 3 行图例（模型 / 工具 / 其他）+ meta 位放 tps；下方逐步骤活跃时长条贴满卡宽，hover 显示 `T# S# · 时长`。

**当前上下文**：左对齐 `≈1.0k / 200.0k`，右对齐占比大数字；条高 22px；图例 3 列网格；压缩预留（斜线）与最大输出预留（交叉斜线）各给一个说明 chip；触发线保留虚线 + title。

**时间线**：见第 6 节。

**上下文浏览器**（重构最大的一块）：

```
+-- 工具栏：步骤 select · 搜索 · 条目/DNA 切换 · 全量/增量 ---+
| 左索引 220px          | 右条目列表（限高 520 内滚）        |
| ● 系统提示词  3 ≈573  | [组头 系统提示词 3 条 ≈573 5.9%]   |
|   5.9%  ▓▓░       Δ — |  ▸ systemBase · preamble ≈320     |
| ● 工具定义    7 ≈184  |  ▸ toolDefinitions · read [pi] ≈26 |
| ...                   | [组头 工具调用 24 条 ≈212 2.2%]    |
+-----------------------------------------------------------+
```

- 左索引每行：色点 + 正式标签 + 条数 + ≈token + 占比 + Δ 徽章；点击聚焦该分类（右列表只显示该组，组头保持），再点清除。
- 右列表按分类分组，组头 sticky 在滚动容器顶部；`systemBase` / `toolDefinitions` 默认折叠，`user` / `toolCalls` / `toolResults` 默认展开。
- 条目行 chip 用 `cat.*` 标签，工具来源 chip、技能 chip、错误标记保留；错误行左侧 2px 红边。
- DNA 视图共用同一滚动容器，行首 `#序号`（最新在上），chip 同色。

**事件**：类型 pill（带计数、选中态）+ 行式列表：左固定宽时间（等宽）+ 类型色点 + 文本 + 位置 chip（可点击跳到浏览器对应步骤）+ 右对齐 Δ 徽章（正绿 / 负红 / 0 灰）。

**工具**：行式列表而非全宽表格：`名称 [来源] ▓▓▓▓░░ 8 次 · ok 8 · err 0 · 0.96s · ≈1.2k`，条形按调用数归一，窄屏时条形换行到第二行。

**文件**：保持 `<details>` 列表；路径等宽字体、类型 chip、`+N −M` 绿/红。

**命令**：左 rail 收窄为 3 行摘要 + 「值得注意」三项；右列表行式：状态点 + program chip + 命令首行 + 时长 + 时间，失败/超时行左侧红边。

**Agent 家族**：成员卡 span 4，卡内含上下文占用微条；委派表列宽收敛，长文本 `line-clamp:2` + `title` 展开。

### 5. 交互契约

保留并接线：

| 控件 | 语义 |
|---|---|
| 全量 / 增量 | 图与浏览器表格同步：增量柱以 0 为基线，正增量向上、负增量（压缩）向下 |
| 步骤 / 轮次 | 按轮聚合：值取轮末步的累计组成，增量取**本轮各步 `delta` 之和**（等价于轮末累计减轮首前一步累计，含本轮首步相对上一轮的变化），柱变宽，刻度标 `T#` |
| 耗时 | 柱图上叠加 `activeMs` 折线，右侧独立刻度两条 |
| 总览 | 整宽堆叠带，高 120，四分位标记；与横向滚动视图互斥 |
| DNA | 只在浏览器内切换列表形态（时间线工具栏不再有这个按钮） |
| 分类行点击 | 过滤条目列表（新增） |
| 色块 / 图例 | 保留 `title` 读数；不做点击高亮（避免第二个"看着能点"的控件） |

删除：`自适应`（没有算法支撑，`总览` 已覆盖长会话场景）。

当前实现里 `applyToggles` 只写 body 属性而 CSS 从不响应，这是死按钮的根因。改为：所有视图变体由客户端重绘 SVG，服务端只预渲染默认视图（全量 / 步骤），JS boot 后接管。这也是让 4 种变体只实现一遍、而不是服务端客户端各一套的办法。

客户端重绘浏览器面板会丢掉服务端渲染的 chip，因此 `InteractivePayload.items` 追加四个字段：`skill`（`item.skillName`）、`src`/`srcLabel`（工具来源，取自 `report.tools`，仅在 `kind === "toolDefinition"` 时有意义）、`at`（`item.timestamp`）、`len`（`item.originalLength`）。同时 `payload.tools` 追加一份 `{name, source, sourceLabel}` 索引，避免每行重复字符串。这些都是纯追加，`schema` 仍为 2。

### 6. 时间线几何

- 柱宽自适应：`BAR_W = clamp(6, 24, 1050 / steps)`，步数少时柱变宽填满卡宽，步数多时保持细柱并在容器内横向滚动。
- 高度 240：顶部 26px 旗标 lane（圆点 8px + 计数角标），主体 150px 柱区，轴下 24px 轮次带，余量给刻度与留白。
- y 轴只 3 条刻度（0 / 半 / 顶），10px 文字；不再画 4 条。
- 轮次带块内显示 `T#` 与步数，hover 有 title。
- 旗标折叠：相邻同步的多个事件合并成一枚 + 计数角标（现状已经做了计数，保留）。
- 选中步骤详情：并入时间线卡底部，不单独成卡；chip 可点跳到浏览器。

### 7. 标签与 i18n

- 补 `browser.system`；JS 重绘一律走 `dicts[lang]`（`cat.*` / `browser.*`），不输出内部 id。
- 新增约 25 条键（`rail.*`、`cardMeta.*`、`chip.*`、`bar.aria` 等），en/zh 同步。
- 新增两条守门测试：① 渲染源码里所有 `key: "..."` 与 `GROUP_LABEL_KEY` 的值都必须存在于 `DICT`；② 渲染出的 HTML 可见文本不得包含 10 个分组 id 与 16 个分类 id 的字面量（`data-*` 属性除外）。
- **页面内语言切换的覆盖范围**：现状 `applyLanguage()` 只换带 `data-i18n` 的节点，于是服务端渲染的图例、表格、详情、`title` 在切换后仍是旧语言——这本身就是一个「按了只变一半」的假交互。两条路：
  - **(a) 补全**（已定）：所有服务端文本节点加 `data-i18n` + `data-i18n-params`（JSON 参数），`applyLanguage` 用同一套插值重写，切换后重绘客户端区域（时间线、浏览器、详情）并同步这些节点。约 30–40 个节点，改动摊在已经在改的 render 模块里。
  - **(b) 删掉**（不采用）：语言只由 `--lang` 决定、页面内不再给按钮。成本更低，但报告共享给另一种语言的读者后无法就地切换，而 README 已承诺页面内可切换。

### 8. 体积与降级

CSS 约 2.3 KB → 9–11 KB，客户端 JS 约 12 KB → 18 KB；时间线服务端 SVG 体积略增（默认视图保留），payload 不变。总量离 16 MB 预算还有三个数量级，降级链逻辑不动。

## 我的取舍（需要时可以推翻）

- **删掉「自适应」而不是实现它**：没有算法定义"自适应"该怎么分桶，`总览` 已经解决长会话的概览需求，留一个语焉不详的按钮比删掉更糟。
- **图例不用表格**：Token 与耗时两张卡的表格只有 4 列、数字短，全宽表格把 1400px 摊给 8 个字符是空白的主因；改成图例行后成本退到 `title` 与 meta 说明里。
- **时间线改成客户端重绘**：4 种视图 × 2 种粒度如果服务端各预渲染一套，HTML 会膨胀且必然与客户端行为漂移；只预渲染默认视图，其余在客户端算。
- **不做浅色主题**：报告是给人看会话内容的，内容区（`<pre>`）在浅色下对比度不好调，且没有用户提出。令牌结构留着。
- **语言切换补全而不是删掉**：删掉更省事，但 `--lang` 是生成期决策，一份中文报告就没法给英文同事看；补全的代价是每个服务端字符串多一个 `data-i18n` 属性与一条守门测试。
- **轮次增量取本轮各步 `delta` 之和**，不是「轮末减轮首」：后者会漏掉本轮首步相对上一轮的变化，单步轮会恒为 0。
