# pi 1.6 只读渲染结果兼容设计

## 目标与约束

- 修复 `pi-subagents` 在 pi 1.6 下残留运行状态行的运行时故障，以及 `pi-subagents`、`pi-ask-user` 的 1.6 类型检查错误。
- 保持 peer 范围 `>=1.5.0`，不修改任何 `peerDependencies` / `devDependencies`。
- 渲染结果归被调用组件所有；调用方只读。调用方需要裁剪或扩展时，生成自己拥有的新数组，不使用类型断言绕过只读契约。
- 不改变现有画面内容、组件缓存职责或公开交互。

## 方案

采用不可变派生：

1. `TranscriptBody.render()` 返回 `readonly string[]`，明确其输出由内部 `Container` 所有。`TranscriptOverlay` 将 body 行与运行状态行组合成新的 overlay 自有数组，不写回 body 缓存。
2. `pi-ask-user` 的详情预览先计算非空内容末尾，再通过 `slice()` 得到预览自有数组；不再对 `Markdown.render()` 的返回值执行 `pop()`。
3. 新增回归测试，向 overlay 提供可复用的 body 渲染数组并断言组合运行状态行后原数组不变。现有指示器生命周期测试继续覆盖状态切换与停止后的清除。

## 备选方案

- **复制后继续原地修改**：可以满足运行时约束，但处理流程仍以可变数组为中心，所有权边界不如不可变组合清晰，不采用。
- **提高开发依赖到 1.6**：只能发现部分类型问题，不能修复运行时写回，且不符合保持依赖声明不变的要求，不采用。

## 验证

- 新回归测试在旧实现上失败、在新实现上通过。
- 两个受影响 package 在现有 1.5.0 环境下通过测试与 typecheck。
- 同一代码在临时 1.6.0 环境下通过相关测试与 typecheck。
- 全仓测试、typecheck、lint 无回归。
